# Collaborative gearbox simulation

Open the repository root with Unity 6000.6.0f1 and use `Assets/Scenes/GearboxTraining.unity`. The original root `GearboxAssembly.unity` is an earlier workcell without the completed assembly manager. The `thesis/` and `.simulation-check/` copies are separate projects; these changes apply to the root project and its prepared Training scene.

The existing behaviour tree and 13-operation order are retained: six internal parts are received and assembled by the worker; the robot seats the housing, inserts the internal assembly and seats the lid; the worker receives and tightens the four screws in the existing order. This is the project's existing division of assembly operations, including robot fixture insertion. Ownership stays with the robot until the receiving handshake completes. Worker assembly starts after robot retreat. The default retreat withdraws 0.6 m horizontally away from the worker along world -Z and lifts 0.2 m; the direction and both distances are configurable and the candidate path is checked.

## Implementation and scene wiring

- `GearboxGameSimulation.cs`: keeps the existing tree and rack/fixture layout; drives phased motion, worker stance changes, the receiving handshake and release/retreat sequence.
- `GearboxCollaboration.cs`: Inspector settings, separation modes, collision checks, latched protective stop, cancellation, confirmation and gizmos.
- `GameRobotIK.cs`: hidden planning model only. The visible source robot and its six ArticulationBodies remain active. Joint targets follow acceleration- and speed-limited commands. Cartesian waypoints use the previous IK solution to maintain a consistent branch. Candidate trajectories are sampled before movement; physics feedback is checked before completing a move.
- `AssemblyBehaviourTree.cs`: configurable whole-action deadlines while retaining the existing tree and exception-to-failure behavior.
- `RobotGripper.cs`: exposes the existing width measurement to the coordinated controller.
- `WorkerMovement.cs`: CharacterController walking with acceleration, braking and bounded turning.
- `RobotArmController.cs`: smooth joint profiles account for nominal acceleration limits; configurable gravity feedforward applies opposing joint torques from subtree masses/centres of mass, capped by authored drive force limits. HoldPosition stops target progression. The feedforward controller is needed to remove static gravity sag at extended poses; payload loads are still not modeled.
- `WorkerReceivingRig.cs`: component beside the humanoid Animator; right-hand IK with imported wrist-frame calibration measured after an IK solve, blended weights, head orientation, reach checks and grasp confirmation. A bounded additive torso posture brings tabletop actions into reach; it does not lengthen arm bones. Existing Idle/Walk/HandOver/Place clips and transitions remain available.
- `GearboxRobotBuilder.cs` and the scene configuration command: use convex cylinder meshes for cylinder joint housings/seals, replacing capsule colliders that exaggerated thin seals.
- `Worker.controller` and `WorkerAnimationSetup.cs`: enable the base layer IK pass, including when regenerating the existing animations.
- `GearboxGameCheckpoints.cs`: restore articulation reduced coordinates only at an explicit checkpoint restore, rather than trying to replay a motion command.
- `GearboxCollaborationInspector.cs`: live phase, ownership, separation and stop readouts with local stop/confirmation controls.
- `GearboxCollaborationChecks.cs`: scene configuration and batch checks. The existing `GearboxGameChecks` falls back to the prepared Training scene if the old assembly scene lacks its manager.

In Edit Mode run **Tools > Gearbox Demo > Configure Collaborative Simulation** on the Training scene. This adds/retains the simulation component on the existing assembly manager, saves its settings and enables Animator IK. Existing manager references supply the robot, six joints, gripper attachment point, Animator and right palm marker. The configuration command adds the receiving rig beside the Animator so reach, blend and torso settings persist in the Inspector; runtime installation remains a fallback. No Animation Rigging package is required.

Select the assembly manager to edit settings. Optionally assign `handoverTarget` (world gripper pose) and `receivingStance` (worker ground position); empty references retain station-relative placement. A target must be reachable by both participants. A bad stance/target stops with an explanation; no arm stretching or robot teleportation is used to satisfy it. Hand targets include the existing palm marker offset. The default handover presents the part horizontally toward the worker, keeping wrist links behind it. `workerGraspOffset` separates the receiving palm from the robot grip, in grip-oriented world metres. Tune it to the actual workpiece surface; its default is 0.04 m along the grip axis. Finger opening/closure uses the existing gripper width calculation and configured finger speed. The lid uses an Inspector-configurable offset edge grip and chord half-gap (`lidGraspPosition`, `lidGraspEuler`, `lidGraspHalfGap`) to keep the wrist away from the protruding output shaft; its values are specific to the supplied CAD and must be retuned for replacement parts. The worker first withdraws the hand, waits for the robot to settle, and then reaches from the exposed side. A blocked worker path times out using its CharacterController.

`simulatedGraspSensor` defaults to a simulated confirmation after continuous valid palm position, rotation, readiness, tracking and ownership for `graspDwell`. Disable it to require `ConfirmWorkerGrasp()` from an animation event, UI or external simulated grasp sensor. The event alone does not bypass the contact and dwell checks. `WorkerReceivingRig.ReadyToReceive` can reject a receiving attempt. This is pose-based simulated grasp confirmation, not a physical grip-force measurement or a new finger animation asset.

On a fault, cancel, tracking failure or timeout the robot retains its payload, stops target progression and freezes simulation time. Emergency and protective stops latch. Play/Step cannot override them. Explicit Reset returns to the initial rack and stays idle; a separate Play/Step/readiness command is required. Reset and checkpoint restoration intentionally restore poses and are not motion trajectories. Payload attachment uses world-pose-preserving parenting without releasing to gravity between owners.

## Safety basis and limitations

Status verified on 7 October 2026 from ISO's catalogue:

- [ISO 10218-1:2025](https://www.iso.org/standard/73933.html), edition 3, published February 2025: industrial robot safety; the previous 2011 edition is withdrawn.
- [ISO 10218-2:2025](https://www.iso.org/standard/73934.html), edition 2, published February 2025: integrated robot applications and cells; the previous 2011 edition is withdrawn.
- [ISO/TS 15066:2016](https://www.iso.org/standard/62996.html) remains published/current, confirmed in 2022, with stage 90.92 (to be revised). ISO/AWI 15066-1 is under development; it is not a published replacement. The technical specification supplements collaborative application guidance. Public catalogue descriptions were reviewed; this implementation is not a clause-by-clause compliance assessment.

Relevant task hazards include unexpected startup/motion, loss of tracking, collision with a person, trapping a hand between part/tool and fixtures, crushing at robot joints or the table, loss of a carried part, failed or premature transfer, unreachable receiving posture, obstruction during worker relocation and unsafe recovery. Tooling, workpiece geometry and the completed cell must be assessed together. Deliberate receiving contact does not make other body contact acceptable.

Implemented simulation safeguards are speed reduction with worker proximity, monitored-standstill mode, reduced interaction speed, body-region clearance checks including carried payload, equipment/link envelopes and separate clearance proxies for the authored visual fingers (whose physical colliders are disabled), sampled candidate-path checks for actual collider shapes and the payload, pose/ownership prerequisites, grasp dwell/confirmation, timeouts, latched emergency/protective stops and explicit reset. The receiving hand can contact the gripper/part only in the receiving/release/retreat window; other links and body regions remain monitored. The housing uses its conservative box during transport and its concave CAD mesh after seating, so the hollow interior is available for insertion checks. Built internal parts use convex CAD mesh colliders instead of square whole-part boxes; reset restores the loose-part boxes. Convex hulls still approximate teeth, holes and recesses. An explicit Insertion phase permits only internal-assembly/housing mating while the internal root is laterally aligned within the configured pose tolerance, within 3 degrees of its target orientation and inside the 0.25 m vertical insertion stroke. This accommodates CAD tooth/hull overlap; gripper, person, equipment and unrelated part contacts remain checked. The lid has a matching aligned 0.18 m seating stroke allowing only its housing and already seated internal-assembly mates (including carrier pins and output shaft). These exceptions are geometric sequencing, not contact-force validation. Housing supports are sized to its actual underside; carrier support posts are narrowed and moved outside the spur gear envelope. `fixtureContactTolerance` (default 0.003 m, demo tuning) permits only upward housing/support seating contact within the target pose tolerance; it does not exempt people or arbitrary obstacles. Robot self-collision handling remains the project's authored ignore matrix and must be reviewed separately.

**Every numerical setting is demo tuning, not a standards-derived safety threshold.** Defaults (metres, degrees and simulated seconds) exist to exercise the model and must be calibrated to the scene: separation 0.08/0.35, equipment clearance 0.015, link radius 0.045, Cartesian speed 0.3 m/s, joint speed 35 deg/s, nominal acceleration 80 deg/s², close-speed fraction 0.2, grasp tolerance 0.018 m / 35 deg, dwell 0.4 s, grasp timeout 12 s and whole-action deadline 180 s. `assemblyLeanDegrees` is capped at 30 degrees in the receiving-rig Inspector and defaults to 25; review that posture against the avatar and workbench. The worker uses configurable approximate body-region spheres (`torsoRadius`, `limbRadius`, `receivingHandRadius`), not measured anthropometry. Joint command acceleration limiting is not a guarantee of measured articulation acceleration or torque. Physics solver settings, inertia, drive gains, frame rate and simulation time scale affect actual motion.

Unity physics, Animator IK and these scripted checks are **not safety-rated or certified**. There is no measured stopping-distance model, certified sensing, functional-safety controller, force/pressure limiting, real contact-force validation or hardware emergency-stop circuit. Sampled paths can miss hazards between samples, and moving obstacles may enter a previously clear path. Worker IK is reach/pose checked and the walking controller collides with equipment, but there is no swept mesh-based human-arm collision controller or physical finger grasp. Final seating retains the existing AssemblyTarget snap tolerance; ownership handover never snaps. Collider approximations can cause false stops or miss shape details; authored equipment and worker collider coverage must be inspected. The handover contact exemption is a simulation policy, not permission for real unvalidated contact. This simulation must not be used to establish real-world safety compliance.

## Validation

Batch commands (from the root project; quote the Unity executable path):

```powershell
Unity.exe -batchmode -nographics -projectPath <root> -executeMethod GearboxDemo.Editor.GearboxCollaborationChecks.RunStaticBatch -quit -logFile collaboration-static.log
Unity.exe -batchmode -nographics -projectPath <root> -executeMethod GearboxDemo.Editor.GearboxCollaborationChecks.RunBatch -logFile collaboration-scenarios.log --gearbox-demo
Unity.exe -batchmode -projectPath <root> -executeMethod GearboxDemo.Editor.GearboxGameChecks.RunBatch -logFile collaboration-workflow.log --gearbox-demo
```

The existing full workflow check renders screenshots, so run it with graphics enabled. `GearboxGameChecks.RunFinalBatch` combines scene configuration/static checks with that complete workflow check. `RunLateBatch` and `RunLidBatch` are diagnostic prepared-fixture checks, not complete-sequence evidence. Read the fresh report files rather than treating earlier `game-simulation-report.txt` results as evidence for this implementation.

Manual Play Mode checks:

1. Successful handover: Play the prepared scene (training readiness, or launch with `--gearbox-demo`). Watch approach, grasp, lift, transport, steady receiving, confirmation, unchanged transfer pose and retreat. Verify the worker only assembles afterward and all existing operations complete.
2. Unreachable target: assign a distant handover marker; expect a latched stop with robot retaining the part. Correct it, Reset and explicitly restart.
3. Absence/tracking: disable the worker or Animator during motion; expect a protective stop. Re-enable, Reset and restart explicitly.
4. Collision: insert a BoxCollider in the transport path, near the elbow, gripper or carried part. Expect blocked-plan or live-clearance stop. Check table/tray geometry and all carried internal parts.
5. Failed grasp: set ReadyToReceive false or offset/rotate the palm outside its tolerances. The robot must retain ownership and time out. Do not use a pose tolerance increase to disguise an invalid rig.
6. Confirmation timeout: turn simulatedGraspSensor off and send no event. Transfer must not occur. Repeat with ConfirmWorkerGrasp after a valid stable pose to exercise event confirmation.
7. Emergency stop: stop in each motion/transfer phase. Verify held world pose stays steady, Play and Step fail, Reset stays idle, and explicit restart works.
8. Cancellation/protective reset: call CancelOperation during carry and while the worker holds the part. Verify retained payload, no duplicate ownership, reset occupancy and rack restoration.
9. Monitored standstill: choose that mode and enter its configured zone. The stop must latch. This mode can prohibit the demonstration's close moving approach; validate the cell staging/stance for that selected policy.
10. Inspect humanoid posture, joint limits, support contacts, animation transitions, reach gizmos and measured physics motion in the Unity Editor. Reject stretched elbows, wrist flips or fixture penetration rather than bypassing the safeguards.

See `COLLABORATION_VALIDATION.md` for actual execution results and outstanding tests.

### Worker proportions

The Training scene has a uniform 1.08 worker-root scale, preserving the floor pivot and scaling the mesh, bones and CharacterController together. The body clearance proxy radii are scaled with it. Default receiving stance Z is at least 1.18 to leave room for the larger walking capsule. Part geometry remains unchanged; physical print measurements are needed for an accurate real-world size ratio. Tools > Gearbox Demo > Resize Worker to Adult Scale reapplies this absolute scene scale without multiplying it repeatedly.
